# 飞书 Word 批量导入工具 

**正式版 · Windows · 独立 Python 虚拟环境 · 多子表 · 启动时选择子表**

本工具在启动时先选定要操作的子表，再把对应文件夹中的 `.docx` 邮件内容，按「**所选子表 → 对应文件夹 → 候选编号**」准确定位到飞书多维表格的**已有记录**，填写「邮件主题」「邮件正文」。支持先预览、只填空白、生成 Excel 差异报告、人工审批后选择性覆盖。

**不会新增候选人，也不会改动「候选编号」「候选人」列。** 有写入操作的菜单需要人工输入全部大写的 `YES`，小写 `yes` 不会执行。

## 一、安装与第一次启动

### 1. 准备环境

- Windows 10/11；安装 Python 3.10 或更高版本，推荐 3.12 或 3.13。
- 将完整压缩包**全部解压到本地可写文件夹**，例如 `D:\飞书Word批量导入工具\`。不要求放在磁盘根目录，不建议放在 `Program Files` 或云同步目录。
- 双击 `双击首次安装环境.bat`。它会在**工具所在目录**创建 `.venv`，安装 `requirements.txt` 中的依赖，不向其他 Python 项目安装依赖。
- 安装窗口提示选择 pip 下载源：直接回车或输入 `1` 使用阿里云；也可以选其他源，见下一节。安装成功后会运行独立的 `检查独立环境.py` 进行检查。
- 首次联网安装通常只需要做一次。以后直接双击 `双击启动工具.bat`，自动使用 `.venv\Scripts\python.exe`，无需手动激活虚拟环境。

**环境检查（可选）：** 在工具文件夹打开 PowerShell，运行：

```powershell
.\.venv\Scripts\python.exe -B .\检查独立环境.py
.\.venv\Scripts\python.exe -m pip check
```

如果出现 `依赖检查通过`，并且 `pip check` 报告 `No broken requirements found.`，说明核心依赖可导入且没有检测到依赖冲突。pip 提示有新版本可用只是通知，并非安装失败。

### 2. 自行选择 pip 下载源

直接双击 **`双击首次安装环境.bat`**，在安装窗口选择编号，不需要修改任何脚本、替换文件，也不会永久修改系统 pip 配置。

| 编号 | 下载源 | URL |
|---|---|---|
| `1`（默认） | 阿里云 | `https://mirrors.aliyun.com/pypi/simple/` |
| `2` | PyPI 官方 | `https://pypi.org/simple/` |
| `3` | 中国科学技术大学 | `https://mirrors.ustc.edu.cn/pypi/simple/` |
| `4` | 华为云 | `https://repo.huaweicloud.com/repository/pypi/simple/` |
| `5` | 清华大学 | `https://pypi.tuna.tsinghua.edu.cn/simple/` |
| `6` | 自定义源 | 输入完整的 HTTPS 软件包索引 URL |

源选择**只对当前安装有效**。已创建 `.venv` 时再次运行安装程序，会复用该环境并检查、补装缺少的依赖，而不是删除或重建。若某个下载源超时，可以按 `Ctrl+C` 停止，待安装进程退出后重新启动安装程序并选择其他源。

也可以在工具文件夹的 PowerShell 中手动安装（使用下表任意 URL 替换阿里云 URL）：

```powershell
.\.venv\Scripts\python.exe -m pip --isolated install -r requirements.txt --index-url https://mirrors.aliyun.com/pypi/simple/ --timeout 10 --retries 1
```

**注意当前目录**：相对路径 ` .\.venv\Scripts\python.exe` 只在工具文件夹中有效。安装源无法解决 Windows 对 Python 文件写入的权限限制；若出现 `PermissionError`，需单独排查。

## 二、配置飞书

### 1. 创建飞书应用并授权

1. 在 [飞书开放平台](https://open.feishu.cn/app) 创建企业自建应用。
2. 取得 **App ID** 与 **App Secret**，按当前飞书开放平台权限要求开通多维表格记录读取、更新权限，并发布生效。
3. 在**目标多维表格**中使用「添加文档应用」等入口授予应用相应的访问与编辑权限。仅在普通「分享协作者」中搜索通常不等同于添加文档应用。
4. 双击 `双击启动工具.bat` 时按提示输入 App ID 和 App Secret。**App Secret 不写入 config.json**，也不要分享给他人。

### 2. 填写 config.json

把 `config.example.json` **复制**为 `config.json`（注意不是改名删除示例文件），填入实际 `app_token` 和各子表 `table_id`。

| 字段 | 来源及作用 |
|---|---|
| `app_token` | 目标多维表格网址 `/base/` 后面的 ID（整份表格共用） |
| `T1 mapping` 的 `table_id` | 浏览器点击 `T1 mapping` 子表，取网址中 `table=` 后的 `tbl...` |
| `T2 mapping` 的 `table_id` | 浏览器点击 `T2 mapping` 子表，取网址中 `table=` 后的 `tbl...` |
| `folder` | `""`：每次弹窗选择 Word 文件夹；也可填本地文件夹绝对路径 |

**table_id 获取方法：**

```text
# 1. 在浏览器中打开飞书多维表格。
# 2. 点击左侧的「T1 mapping」子表。
# 3. 查看浏览器地址栏，找到 table= 后面的内容。
#    例如：https://xxx.feishu.cn/base/xxxxx?table=tblAbc123
#    则 T1 的 table_id 为：tblAbc123
# 4. 点击「T2 mapping」子表，按相同方法获取 T2 的 table_id。
# 5. 将下方示例值替换为实际获取的 ID。
# 注意：
# - 每个子表有独立的 table_id。
# - table_id 与 App ID、App Secret、app_token 不同。
# - 不要填写子表名称，必须填写对应的真实 ID。
```

例如网址：

```text
https://xxx.feishu.cn/base/BaseDemoToken123?table=tblDemoT1ABC&view=vewDemo123
```

则只填写 `app_token = BaseDemoToken123`、`table_id = tblDemoT1ABC`，**不要带 `base/`、`&view=...`**。程序也支持从误粘贴的 URL 中提取纯 ID，但推荐直接填纯 ID。若从知识库 `/wiki/` 进入表格，可能需要通过飞书 API 查询真正的 `app_token`。

**配置结构示例**（`config.example.json` 内有详细说明）：

```json
{
  "app_token": "BaseDemoToken123",
  "tables": [
    {"name": "T1 mapping", "table_id": "tblDemoT1ABC", "folder": ""},
    {"name": "T2 mapping", "table_id": "tblDemoT2DEF", "folder": ""}
  ]
}
```

> 上述 ID 仅用于说明，不能直接访问飞书。Windows JSON 路径中反斜杠需要写双反斜杠，例如 `"D:\\候选人邮件\\T1"`。如果 `folder` 留空，运行菜单 1、2 时只会为**本次选中的子表**弹出文件夹选择窗口；取消选择即跳过该子表。

**本地配置检查：** 双击 `双击检查配置.bat`；它只检查 ID 格式和候选编号提取，**不联网、不读写飞书**。检查通过并不代表应用已获得飞书访问权限。

## 三、Word 文件命名与提取规则

```text
电脑上的 T1 文件夹\
    C001_候选人姓名.docx
    C062_张三.docx
电脑上的 T2 文件夹\
    C001_候选人姓名.docx
    C125_李四.docx
```

- **只读取文件名最前面的候选编号**，例如 `C001_候选人姓名.docx` 仅用 `C001` 匹配对应子表的「候选编号」；姓名**不参与匹配**。
- T1 与 T2 通过两个独立 `table_id` 查找，同一个编号可在两个子表中分别存在，**不会串表**。
- 每个子表只扫描所选文件夹**第一层**的 `.docx`，不递归子目录；同一文件夹编号重复、飞书中同一编号多条记录或无匹配时，跳过并记录异常。
- Word 的首条非空行必须是 `主题：邮件标题`（支持英文冒号 `:`），这一行去掉前缀后写入「邮件主题」；其余正文（包含空行）写入「邮件正文」。
- 支持正文中的普通段落与表格文字；不保证提取图片、文本框、页眉页脚、批注、修订记录等。正文保存为**纯文本**，不保留 Word 字体和版式。
- `.doc` 不是 `.docx`：需在 Word 中另存为 `.docx`。
- 文件名中候选编号必须明确且唯一，例如 `C001_候选人姓名.docx` 或 `C001.docx`。

## 四、启动先选子表，再使用菜单 1～4

在 `双击启动工具.bat` 打开的黑底白字窗口中，按提示输入 App ID / App Secret。**进入主菜单之前，先选择本轮目标子表；选择在当前启动会话内保持有效。**

### 1. 启动前置步骤：选择目标子表（方案 A）

例如 `config.json` 配置了 T1、T2 两张子表时，屏幕显示：

```text
=============== 第一步：选择本次目标子表 ===============
[1] T1 mapping
[2] T2 mapping
[0] 不选择任何子表（不读写，仍可返回菜单重新选择）
可单选 1、多选 1,2；输入 0 或直接回车表示不选择。
请输入子表编号：
```

| 输入 | 本轮选中的子表 | 后续处理范围 |
|---|---|---|
| `1` | T1 mapping | 只查询 T1、只读取 T1 文件夹，写入也仅限 T1 |
| `2` | T2 mapping | 只查询 T2、只读取 T2 文件夹，写入也仅限 T2 |
| `1,2` | T1 + T2 | 分别按各自文件夹、编号和 `table_id` 处理 |
| `0` 或直接回车 | 无 | 菜单 1～4 均不执行任何读写；可按 5 重新选择或 0 退出 |
| `1,3`（仅配置两张表时） | 无效 | 要求重新输入，不会误选择未配置的子表 |

- 当前选择会显示在后续主菜单上方，**菜单 1、2、3、4 均严格使用该范围**。
- 如需更换子表，使用菜单 **`5. 重新选择目标子表`**，无需关闭程序或重新输入飞书应用凭证。
- 菜单 3 和 4 即使读取了一份同时包含 T1/T2 审批记录的 Excel，**也只会核验及覆盖当前选中的子表**；未选中的已审批项目会在执行结果报告中写明「本次未选中该子表」，不访问它的飞书记录。
- 子表编号来自 `config.json` 的 `tables` 顺序，新增 T3/T4 时会自动增加选项。Word 文件名中的候选编号仍是唯一匹配条件，姓名不参与匹配。

### 2. 原有业务菜单（已新增重新选择入口）

完成子表选择后，才会显示功能菜单：

```text
1. 生成预览 + 差异审核 Excel（不修改飞书）
2. 正式只填空白 + 生成差异审核 Excel【写入飞书】
3. 审核覆盖预检（不修改飞书）
4. 根据 Excel 人工审批正式覆盖【写入飞书】
5. 重新选择目标子表
0. 退出

重要：菜单 2、4 确认写入时必须输入全部大写 YES；小写 yes 不执行。
```

| 菜单 | 适用场景 | 具体行为 | 是否写入飞书 |
|---|---|---|---|
| **1 预览** | 首次导入前验证文件/编号/子表映射 | 读取 Word 和飞书，生成 Excel 差异审核报告，标注拟填空字段与异常 | **否** |
| **2 只填空白** | 预览核对无误后，批量补充邮件 | 重新读取飞书，只填写空白的「邮件主题」「邮件正文」，非空字段不覆盖，同时生成最新差异报告 | **是，需大写 `YES`** |
| **3 覆盖预检** | 人工在 Excel 审核完差异后 | 只检查 Excel 标注为「覆盖」的项目，验证表/记录/编号/旧值/校验标识；输出预检结果 | **否** |
| **4 审批覆盖** | 预检无异常且确认用 Word 替换已有内容 | 只对**选中子表**重新验证飞书旧值、备份原内容，覆盖 Excel 批准的目标字段 | **是，需大写 `YES`** |
| **5 重新选择子表** | 需要从 T1 切换到 T2 或重新多选 | 返回选择界面并更新当前会话操作范围，不执行 Word/飞书业务 | **否** |

**推荐流程：**

1. **先选择目标子表**（例如 `1` / `2` / `1,2`），再选菜单 **1**；仅为选中子表指定 Word 文件夹。查看 `报告\差异审核_日期时间.xlsx` 的「字段处理明细」和「异常与跳过」。这里出现 **`预览：将填写空白` 只表示拟写入，并非已写飞书**。
2. 确认无误后、保持相同子表选择并选择 **2**，指定对应文件夹，在提示时输入**全部大写 `YES`**。程序只补充空白列；填写完成后刷新飞书表格，查看程序输出和报告中的「处理状态」。
3. 若报告「差异审核」工作表中有真正的差异行，在 **A 列「审批状态」** 中逐条选择 `待确认` / `保留` / `覆盖`。仅修改 A 列，不要编辑旧值、新值、编号、ID 或校验标识。保存 Excel 并关闭它。
4. 保持/重新选择需要操作的子表，选择 **3**，输入审核过的 `.xlsx` 完整路径，读取预检报告，确认每个「覆盖」项目可安全执行。
5. 最后保持相同子表范围，选择 **4**，再输入同一 Excel 路径，并输入**全部大写 `YES`**。只覆盖通过审批和校验的字段，其他列不变。核对备份和执行结果。

如果所有记录都是空白，**菜单 2 就可以完成任务，无须使用 3、4**。若只想检查、不修改飞书，只运行菜单 1 或 3。

### 已有内容的保护规则

| 飞书邮件主题 | 飞书邮件正文 | 菜单 2 的处理 |
|---|---|---|
| 空 | 空 | 填写两个字段 |
| 已有内容 | 空 | 只填正文；主题若不同则进差异审核 |
| 空 | 已有内容 | 只填主题；正文若不同则进差异审核 |
| 已有内容 | 已有内容 | 均不覆盖；仅记录差异 |
| 无法唯一匹配候选编号 | 任意 | 整条跳过，生成异常 |

**大写 `YES` 特别提示：**

```text
请输入大写 YES 确认：YES    ← 执行写入
请输入大写 YES 确认：yes    ← 取消写入（不是报错）
```

运行中若出现接口错误、网络超时或终止，**部分先前提交的记录可能已经写入**；程序不具备跨批次事务回滚功能。请先检查日志和飞书，不要直接重复覆盖。

## 五、Excel 差异审核的正确方法

正式填空后打开最新 `报告\差异审核_*.xlsx`：

- 「**差异审核**」：仅显示飞书**已有内容且与 Word 不同**的字段，每行一个差异。A 列「审批状态」默认为 `待确认`，可改为 `保留` 或 `覆盖`。
- 「**字段处理明细**」：显示每个 Word 对应字段的原值、新值和处理状态（预览、已填写、保持不变等）。这是检查首次填空成功与否的重点。
- 「**异常与跳过**」：记录文件名、候选编号、重复、类型等问题。
- 「**使用说明**」：保存当前报告的运行参数及审核规则。

**注意**：菜单 3/4 中即使审核 Excel 包含其他子表的「覆盖」行，也会被跳过并写入结果报告；重新选择子表才能处理那些行。不能在空白行随意输入「覆盖」。没有真实的差异项目时，就不需要审批。不要改动差异表中的 ID、候选编号、字段、新旧文本或校验标识。审批后用菜单 **3 → 4**。运行 4 时会核对飞书当前内容与报告旧值是否相等；不相等则拒绝覆盖并提示重新审核。

报告与备份中可能包含候选人联系方式和完整邮件正文，请只保存在有访问控制的电脑或文件夹中，不要公开分享。

## 六、常见错误

| 现象 / 提示 | 应对方式 |
|---|---|
| `.venv` 不存在或缺少依赖 | 双击 `双击首次安装环境.bat`，选择可用的下载源并完成安装 |
| `pip` 提示新版本可用 | 普通提示，不影响依赖已安装成功 |
| `PermissionError` / `No usable temporary directory` | 排查 Python 在 Windows 临时目录的读写权限或安全软件；单纯换下载源不能解决 |
| `app_token 未填写`、`table_id 未填写` | 在 `config.json` 填真实 ID，不是应用 ID、子表名称或完整 URL |
| 404 或 API 路径错误 | 确认 `app_token` / `table_id` 来自同一多维表格，`table_id` 不包含 `&view=...`，应用有访问权限 |
| 403 / 权限不足 | 检查自建应用的 API 权限、生效版本及多维表格中的文档应用授权 |
| 无法识别候选编号或无匹配记录 | 文件名应为 `C001_姓名.docx`；飞书对应子表的「候选编号」字段必须有完全相同的编号 |
| `.doc` 文件 | 用 Word 另存为 `.docx` |
| `字段不是可处理的文本类型` | 检查「候选编号」「邮件主题」「邮件正文」为文本类型，避免公式/附件字段 |
| 审核报告旧值与飞书现值不同 | 审核期间可能有人修改内容，重新生成差异报告并审批 |
| 输入 `yes` 后提示未确认写入 | **必须输入全部大写 `YES`**，否则本轮不执行写入；返回菜单重新操作 |
| Excel 没有差异行 | 属于正常情况；无需菜单 3、4，按需使用菜单 2 填写空白即可 |
| 菜单提示「当前选中：无」 | 启动时选了 0 或回车；使用菜单 5 重新选择子表，不会对飞书进行读写 |
| 审核 Excel 的部分「覆盖」没有执行 | 核查菜单上方所选子表；未选中子表的审批行会记录为「本次未选中该子表」 |
| PowerShell 找不到 `.\.venv\Scripts\python.exe` | 先进入包含 `.venv` 和 `requirements.txt` 的工具文件夹，或双击工具自带 `.bat` |

## 七、数据安全、使用限制与卸载

- 正式使用前，请在飞书复制一份测试表，用 3～5 个 Word 文件验证匹配、字段及权限，再批量运行。
- 菜单 2 和 4 写入飞书前均需要人工确认；程序的读取后校验与批量更新**不是原子事务**。写入时尽量暂停其他人编辑目标字段。
- 涉及邮件正文和候选人信息的报告、备份均可能包含敏感数据，需限制访问权限。`App Secret` 只在启动进程中输入，不写入配置文件。
- `.venv`、`config.json`、`报告/`、`备份/` 均不适合公开上传。
